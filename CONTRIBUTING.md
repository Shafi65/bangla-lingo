# Contributing to BanglaLingo

Thank you for helping! BanglaLingo is a gamified Bengali course for English speakers. You do not need to be technical to help. There are two ways to contribute, and the first needs no setup at all.

## Way 1: Review the Bengali in the app (no setup)

If you speak Bengali, this is the most valuable thing you can do.

1. Open the app (ask the owner for the link) and go to **/reviewer** (add `/reviewer` to the end of the web address).
2. Open a lesson. Mark every exercise, the tip and each word as **OK**, **Needs change** or **Unsure**, and add a short note saying what you would change.
3. Your progress is saved in your own browser. When you are done, use **Export** at the bottom to download your review (CSV or JSON) and send it to the owner.

Spotted a problem while using the app normally? Tap **Report a problem**. It opens a pre-filled GitHub issue. Issues are public, so never put personal details in them.

## Way 2: Make changes by asking Claude

You do not edit files yourself. You describe the change in plain English and Claude makes it.

### Steps

1. Open **Claude Code on the web** (claude.ai/code) and start a new session on this repository (`Shafi65/bangla-lingo`).
2. Paste a request (examples below). Claude reads the project rules in [CLAUDE.md](CLAUDE.md) and follows them. In short: course content is data kept in `content/`, every Bengali item has Bengali script, a Roman spelling and an English meaning, the course teaches Standard Colloquial Bengali as spoken in Bangladesh (with Kolkata variants in notes), and it never copies another app's name or look.
3. **Always work on a branch and open a pull request. Never push to `main`.** Tell Claude: "Work on a new branch and open a pull request." A pull request (PR) is a proposal that the owner can look over before it goes live.
4. **Wait for the Vercel preview link.** After the PR is opened, Vercel builds a private copy of the app with your change and posts a link on the PR. This takes a few minutes.
5. **Open that link on your phone** and check your change really looks right: the Bengali, the English, the buttons and the audio.
6. Fill in the short checklist that appears in the PR, then tell the owner it is ready.

### What "checks must pass" means

Before a change is accepted, these automatic checks must succeed. Claude runs them for you; ask it to "run all the checks and tell me the result".

| Check | What it does |
|---|---|
| `npm run validate` | Checks all course content: format, spellings against the lexicon, no word used before it is taught |
| `npm run validate:strict` | A stricter version of the same content check |
| `npm run build` | Builds the app to make sure nothing is broken |
| `npm test` | Runs the full test suite, including the content checks above |

If a check fails, do not merge. Paste the error back to Claude and ask it to fix it.

### Example prompts you can paste

- "Fix the English meaning of the word for 'water' in the first unit. It should say ... Work on a new branch and open a pull request."
- "This sentence sounds unnatural: *(paste the Bengali)*. In my family we say *(your version)*. Please check it against the lexicon, and if my version fits, update it. Use a branch and a pull request."
- "Add a lesson note about when to use তুমি versus আপনি, in simple English, with two examples. Branch and pull request please."
- "The transliteration of *(word)* looks wrong. Please check it against content/TRANSLITERATION.md and fix it."
- "Here is my exported review file (paste it). Please apply the changes I marked as Needs change, in small pull requests, one lesson each."
- "Run all the checks and tell me in plain English whether everything passes."

## Avoiding clashes with other contributors

Several people may be helping at once.

- **Keep pull requests small.** One lesson, one word list or one fix at a time.
- **Work on one area at a time.** Do not touch a lesson someone else is already changing. Ask the owner if unsure.
- **Start from the latest main.** At the start of each session, tell Claude: "Pull the latest main and start a fresh branch from it."
- If your PR says it has conflicts, ask Claude: "Update my branch with the latest main and fix any conflicts."

## What not to do

- **Never commit keys, passwords or `.env` files.** The app works without them. Secrets live only in Vercel settings.
- **Never invent Bengali spellings.** Every spelling used in a lesson must already exist in `content/lexicon/`. To add a new word, ask Claude to add it to the lexicon first, following [docs/LESSON_PIPELINE.md](docs/LESSON_PIPELINE.md).
- **Never edit `content/audio/` by hand.** Audio is generated by a script. If a clip sounds wrong, report it instead.
- **Do not push to `main`**, and do not merge your own PR unless the owner says so.
- **Do not copy another app's name, mascot, colours, fonts, sounds or pictures.** Streaks and XP are fine; imitating a brand is not.
- Do not paste personal or private details into issues, PRs or prompts.
